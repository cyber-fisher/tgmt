# GraphGPS 训练实验报告

**日期**：2026-08-19
**实验目标**：把活性子图 GNN 编码器由两层 GCN 替换为 GraphGPS（位置/结构编码 + 局部消息传递 + 全局注意力），验证更强的图 Transformer 架构能否在几何代表性指标上超过随机初始化 GCN 与 Jaccard 距离。
**结论一句话**：GraphGPS **全面超过训练版 GCN 与随机版 GCN**（-14% ~ -32%），在 case20 上部分指标（PCE_V）**超过 Jaccard**、其他指标逼近 Jaccard；但 case17 上 Jaccard-multi 仍占优，且 GraphGPS-multi 在 case17 出现与 GCN-trained-multi 相同的多分支坍缩病症。**数据规模（14 case、6382 训练对）是当前实验的核心瓶颈**。

---

## 1. 背景与动机

### 上一轮 GCN 训练的失败点
2026-08-14 的自监督对比学习实验证明：训练版 GCN 相对随机初始化在 case17 仅在两项指标上小幅改善，在 case20 五项全线退步。诊断为 embedding 空间坍缩（Val Pos Sim=0.9977），且当前 GCN 的表达能力已被"11 维节点特征 + 2 层邻域聚合 + 双池化"的架构上限锁死。

### 为什么换 GraphGPS
Rampasek 等 NeurIPS 2022 提出的 GraphGPS 通用框架有三个针对现状的直接好处：
1. **位置/结构编码**注入 GCN 缺失的空间信号——直接对应"活性子图逐边比较对网格平移过敏"的痛点
2. **全局注意力**让活性子图两侧顶点直接交互——不再受 2-hop 消息传递限制
3. **参数容量提升**——187k vs 30k，理论上有更多可训练自由度

已在论文 §2.3（相关研究）里引用 `\cite{rampasek_gps_2022}`，从"引用"到"采用"叙事顺。

## 2. 方案设计

### 2.1 输入数据

**不改活性子图定义**（论文 §3.3.2），只在原有 11 维节点特征上拼位置编码：

| 张量 | 形状 | 组成 |
|------|------|------|
| `X` | `[N, 35]` | 原始 11 维 + RWSE 16 维 + LapPE 8 维 |
| `edge_index` | `[2, 2E]` | 活性边双向（无自环） |
| `num_edges` | scalar | 用于 readout 的 log\|E\| |

**原始 11 维特征（不变）**：
- 标量类 (3)：归一化标量、相对阈值偏差、其绝对值
- 几何类 (3)：相对质心坐标（按包围盒归一化）
- 拓扑类 (1)：归一化度数
- 分割类 (4)：SegmentationId 多尺度 sin/cos 编码

**位置/结构编码（新增）**：
- **RWSE（Random Walk Structural Encoding, 16 维）**：k=1..16 步随机游走的自返回概率 `[P^1_ii, P^2_ii, ..., P^16_ii]`。捕捉节点局部结构指纹。
- **LapPE（Laplacian Positional Encoding, 8 维）**：归一化 Laplacian `L = I - D^{-1/2} A D^{-1/2}` 前 8 个非零特征向量。捕捉图的谱结构。训练时随机翻符号（有符号歧义）。

### 2.2 模型架构

**GraphGPS = 输入投影 + 3 层 GPS Block + 双池化 readout**

```
X[N,35] --(Linear)--> h[N,64]
   |
   v
[GPS Layer × 3]
   每层:  h_local = GINE(h, edge_index)         # 局部消息传递
         h_attn  = MultiHeadAttn(h)             # 全局注意力(4头)
         h       = LN(FFN(LN(h+h_local) + LN(h+h_attn)) + ...)
   |
   v
readout: mean-pool || max-pool || log|V| || log|E|  → L2 归一化 → z[130]
   |
   v
Projection Head (训练时): 2层 MLP → p[130]
```

**关键选择**：
- **局部分支用 GINE**（GraphGPS 官方默认），比 GCN 表达力强
- **全局注意力 4 头**，标准 PyTorch `nn.MultiheadAttention`
- **3 层 GPS**（不是常用 4-6 层）——避免小数据过拟合
- **双池化 + log|V| + log|E|** readout 与原 GCN 一致，便于横向比较

**总参数量**：**186,895**（约为原 GCN 版本的 6 倍）。

### 2.3 训练配置

沿用与 GCN 版本一致的自监督对比学习框架，方便对比：

| 项目 | 值 |
|------|-----|
| 训练/验证/测试切分 | 14 / 3 / 3 case（同 GCN 版） |
| 训练正样本对 | 6382 |
| 验证正样本对 | 1793 |
| 损失 | NT-Xent (SimCLR)，τ=0.1 |
| 优化器 | AdamW, lr=5e-4, weight_decay=1e-4 |
| 学习率调度 | CosineAnnealingLR (T_max=50) |
| Batch size | 16 |
| Epoch | 50 |
| 梯度裁剪 | max_norm=1.0 |
| 加噪副本 σ | 1% 标量范围 |
| Dropout | 0.1 |
| 设备 | CPU（PyTorch 2.13，纯 CPU 实现） |
| 训练耗时 | 约 78 分钟（1 epoch ≈ 90s） |

**GraphGPS 无第三方依赖**：全部用 `torch.nn.MultiheadAttention` + `scatter_add_` + `numpy.linalg.eigh` 实现，未引入 `torch_geometric` / `torch_scatter`，Mac CPU 直接可跑。

## 5. 问题诊断

### 问题 1：case17 multi 配置严重退化
GraphGPS-multi 在 case17 上 NNAE^C 从 single 的 0.00126 骤升至 0.00402（+220%）。这与 GCN-trained-multi 在 case17 上同样的退化模式（0.00142 → 0.00476）**一模一样**，说明：

- 多分支加权依赖分支间几何差异的相对大小做权重
- 训练后的 embedding 空间过于紧凑（Val Pos Sim=0.9928），不同分支间的差异被压缩到同一量级
- 权重稀释 → 简化选出的节点低质量
- **这是训练带来的坍缩副作用，架构升级并未解决**

case20 上未复现此问题（single→multi 只从 0.00102 微升至 0.00117），推测与 case20 拓扑分支更均衡有关。

### 问题 2：Val Pos Sim 仍偏高
虽然 0.9928 比 GCN 的 0.9977 已好，但仍距离理想的 0.85-0.95 区间较远。原因与上一轮相同：
- 对比学习设计过于宽松（负样本均为易负样本）
- 温度 τ=0.1 稀释对比信号
- 无 Barlow Twins 式去相关正则

### 问题 3：数据规模是核心瓶颈
14 case × ~450 训练对 = 6382 pair，训 187k 参数的图 Transformer——**每 34 个参数才有 1 对训练样本**。深度学习经验法则至少要求 1:1，工程实践通常要 1:10。这是最根本的问题。

### 问题 4：数据类型对 Jaccard 天然友好
所有 20 case 均为**小规则合成网格**（最大 12×8×5）：
- 无噪声、无测量伪影、顶点分布均匀
- 阈值微变 → 活性边集合有干净可预测的局部替换
- **这恰好是 Jaccard 的最优场景**
- 学习式方法要赢，需要 Jaccard 明显失败的场景（大规模真实数据 / 高噪声 / 跨分辨率），当前数据集不具备

## 6. 相对上一轮 GCN 训练的核心改进

| 项目 | GCN 训练版 | GraphGPS |
|------|-----------|----------|
| 架构 | 2 层 GCN | 3 层 GraphGPS（GINE + 全局注意力） |
| 节点特征维度 | 11 | 35（+ RWSE 16 + LapPE 8） |
| 参数量 | ~30k | 187k |
| Val Pos Sim（终态） | 0.9977（严重坍缩） | 0.9928（缓解） |
| vs random-GNN 变化 | 部分退步 | **全面改进 -14% ~ -32%** |
| vs Jaccard | 均劣 | case20 上 PCE_V 反超 |
| 训练耗时 | ~25 分钟 | ~78 分钟 |

**GraphGPS 是当前唯一能通过训练带来稳定收益的方案**——但受限于数据，仍不足以全面超越 Jaccard。

## 7. 下一步方案（供组会讨论）

### 数据侧（推荐优先）
**方案 D1（半天）**：对现有 20 case 做重度数据增强
- 每个 case 生成 K 个扰动副本（不同 σ 高斯噪声、局部旋转、下采样）
- 训练对从 6382 扩到 60k+
- 验证"坍缩是否为纯数据量问题"

**方案 D2（1-2 天）**：接入公开数据集
- Bonsai、Nucleon、Tooth（VTK Data）
- Marschner-Lobb（高频振荡，Jaccard 应显著退化）
- Hurricane Isabel（气象仿真）
- **场景多样性突破**——让 GraphGPS 有 Jaccard 打不了的用武之地

**方案 D3（1 周+）**：引入真实医学 CT
- 论文说服力最强，但工作量大

### 模型侧
**方案 M1（1 天）**：把对比学习换成 Barlow Twins 或 VICReg
- 加去相关正则或方差保持项，直接破坍缩
- 目标：Val Pos Sim 压到 0.9-0.95

**方案 M2（2-3 天）**：难负样本挖掘
- 每个 batch 强制加入"同 case 同层级不同分支"作为难负例
- 直接治疗 case17 multi 病症

### 论文定位
**方案 P1**：把当前结果写进论文，主贡献表述为"GraphGPS 相对随机 GCN 的稳定提升 + 数据规模是当前瓶颈"（诚实叙事）

**方案 P2**：主标题保留 GraphGPS，但增加"当前实验限制"章节——避免审稿人质疑
